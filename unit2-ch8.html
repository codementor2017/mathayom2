8.1 Find the Bug ⏱️ 0–10 min

Read this program:

def grade(score):
    if score > 80:
        return "A"
    elif score > 70:
        return "B"
    ...

What is wrong?

The comparison should be >=, not >. If the score is exactly 80, the program will return "B" instead of "A".

Testing finds bugs. Debugging fixes them.

🗣️ Think–Pair–Share (2 minutes):

Why do you think it's easy to miss this kind of bug? Share your thoughts with a partner.

8.2 Testing Strategies ⏱️ 10–30 min

Here are three types of test cases:

  • Normal case: Typical input (score = 75).
  • Boundary case: Edge values (score = 80, 70, 60, 50, 0, 100).
  • Invalid case: Bad input (score = -10, 150, "abc").

👩‍🏫 Tip: Ask students: "Which bugs are hardest to find — normal, boundary, or invalid?" Most will say boundary, because the errors only appear at exact edge values.

8.3 Testing the Grade Calculator ⏱️ 30–50 min

Use the grade calculator from Chapter 6.

Test with:

  • 85 → A
  • 80 → A (boundary)
  • 79.9 → B (boundary)
  • 0 → F
  • 100 → A
  • -5 → Invalid
  • 105 → Invalid

Record results in a debugging log. Fix any bugs.

🗣️ Quick Check (2 minutes):

Which of these tests is the most important? Why?

☕ Break Time ⏱️ 50–60 min

Stretch, hydrate, and reset your brain. When you return, you'll debug and improve a buggy program! 🦁

8.4 Group Activity: Debug and Improve ⏱️ 60–85 min

Work with a partner. Your teacher will give you a buggy program with at least 3 bugs:

  • Wrong comparison operator.
  • Missing return statement.
  • Wrong variable name.
  • Incorrect Boolean operator.

Your task:

  1. Find the bugs.
  2. Fix them.
  3. Test with boundary cases.
  4. Write a debugging log.

👥 Suggested Group Roles

  • Detective: finds the bugs.
  • Fixer: corrects the code.
  • Tester: runs boundary and invalid cases.
  • Recorder: fills in the debugging log.
👩‍🏫 Tip: Provide a simple buggy program, e.g., a triangle validity checker with the wrong comparison or a pass/fail checker missing a return. Keep it short so students can focus on finding bugs, not reading code.

8.4b Sharing & Presentations ⏱️ 85–95 min

Each pair will present their debugging log.

As you listen, ask yourself:

  • Did they find all the bugs?
  • Did they use boundary and invalid cases?
  • Is their debugging log clear?
🗣️ Peer Feedback:

Give one star and one wish.

8.5 Chapter Summary ⏱️ 95–97 min

  • Testing finds bugs. Debugging fixes them.
  • Test with normal, boundary, and invalid cases.
  • A debugging log tracks your testing.
  • Good testers try to break the program.
