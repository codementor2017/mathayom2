5.1 Plan Before You Code ⏱️ 0–10 min

If you build a house without a plan, what happens?

  • It might fall down.
  • It might not have enough rooms.
  • It might cost too much.

Good programmers design the algorithm before writing code.

🗣️ Think–Pair–Share (2 minutes):

Have you ever tried to build or make something without a plan? What happened? Share with your partner.

5.2 The Design Process ⏱️ 10–20 min

Here is the design process:

  1. Step 1: Understand the problem.
  2. Step 2: Identify input and output.
  3. Step 3: Break the problem into sub-problems (decomposition).
  4. Step 4: Design a function for each sub-problem.
  5. Step 5: Write pseudocode.
  6. Step 6: Write the code.
  7. Step 7: Test.
👩‍🏫 Tip: Emphasize that steps 1–5 happen before touching the keyboard. This is where computational thinking pays off.

5.3 Example: Grade Calculator ⏱️ 20–30 min

Let's design a grade calculator.

📥 Input

score

📤 Output

letter grade

🧩 Sub-problems

get score, check ranges, return grade.

📦 Function

grade(score)

Pseudocode:

FUNCTION grade(score)
    IF score >= 80 THEN RETURN "A"
    ELSE IF score >= 70 THEN RETURN "B"
    ...
END FUNCTION

Functions make the design modular and reusable.

5.4 Designing a Program ⏱️ 30–50 min

Let's design a program that calculates the total cost of a shopping cart with discounts.

Rule: 10% discount if total ≥ 1000; free shipping if total ≥ 500; 5% tax.

📥 Input

prices, member status.

📤 Output

final total.

🧩 Sub-problems

  • Calculate subtotal.
  • Calculate discount.
  • Calculate tax.
  • Calculate total.

📦 Functions

subtotal(), discount(), tax(), total().

🗣️ Quick Check (2 minutes):

Why is it useful to break the shopping cart into four functions instead of writing one big program? Discuss with your neighbor.

☕ Break Time ⏱️ 50–60 min

Stretch, hydrate, and reset your brain. When you return, you'll design your own program! 🦁

5.5 Group Activity: Design Your Own Program ⏱️ 60–85 min

Work with a partner. Choose one problem:

  • Movie ticket pricing with age and member discounts.
  • Restaurant bill with tax and tip.
  • Gym membership with age and duration.
  • Electricity bill with tiered rates.
  • Parking fee with hourly rates and daily maximum.

Your task:

  1. Write input and output.
  2. Break into 3+ sub-problems.
  3. Design 3+ functions.
  4. Write pseudocode.

Present your design on a poster. Label the input, functions, and output.

👥 Suggested Group Roles

  • Analyst: identifies input, output, and sub-problems.
  • Designer: names the functions and outlines the pseudocode.
  • Writer: writes the pseudocode clearly.
  • Presenter: explains the design to the class.
👩‍🏫 Tip: Remind students that pseudocode doesn't have to be perfect Python. It should be readable and show the flow clearly.

5.5b Sharing & Presentations ⏱️ 85–95 min

Each group will present their design and pseudocode.

As you listen, ask yourself:

  • Did they clearly identify input and output?
  • Do their sub-problems cover the whole task?
  • Are their functions well-named and logical?
  • Is the pseudocode easy to follow?
🗣️ Peer Feedback:

After each presentation, give one star (something you liked) and one wish (something that could be improved).

5.6 Chapter Summary ⏱️ 95–97 min

  • Design the algorithm before writing code.
  • Break the problem into sub-problems.
  • Design a function for each sub-problem.
  • Write pseudocode before writing code.
  • Functions make the design modular and reusable.

5.7 Key Words

Word
Meaning

Pseudocode

Flowchart

Function
A named block of code that does one job
Design
Planning how to build something
Plan
A detailed proposal
